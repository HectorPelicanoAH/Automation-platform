# Phase 6 — Controlled knowledge improvement and Autohealth

Status: VALIDATION. Local implementation and checks are recorded in the [report](phase-6-report.md); required three-system CI remains pending. The owner approved Phase 6 and explicitly authorized its start with Phases 3–5 CI pending on 2026-11-06. This is a sequencing exception, not a validation waiver or skill activation grant.

## Objective and scope

Make useful discoveries reusable, measurable and reversible, while preserving source permissions and explicit instruction activation. Deliver functional Knowledge & Skills and Autohealth web sections, deterministic local health checks, source-linked knowledge/version history, evaluated skill proposals, approved activation/rollback and honest workflow metrics.

Reuse the SQLite store, bounded incremental index, native execution evidence, generation task metrics and Phase 5 diagnosis/repair records. No external graph database, cloud dependency for manual use or new background service is assumed.

## Implementation milestones within the approved phase

1. **Knowledge lifecycle.** Consume actual completed workflow evidence through bounded deterministic collectors. Classify temporary context, repository knowledge, reusable procedure, architectural decision and possible skill improvement. Persist concise provenance, confidence, source references/revisions/hashes and state. Unchanged ingestion is a no-op; meaningful changes create a new revision and mark obsolete evidence stale. Produce private concise documentation for reviewed records, with history and rollback, rather than writing into external sources or platform Git automatically.
2. **Skills and evaluation.** Register immutable bundles outside all discovery paths, preserve parent/version/content hashes and exact diffs, explain the observed problem and expected benefit, and record actual comparable evaluations. Reuse existing inactive candidates only after checking their recorded failures/limitations. Build explicit activation and reversal controls with path boundaries, conflict/stale-base checks, journals and exact-hash review. Format validation alone never counts as behavioral evaluation. Direct Codex use must remain possible through a reviewed standard skill export without the application/database.
3. **Metrics.** Extend existing task/run records with missing search/reuse/invocation evidence where needed. Report retrieval bytes/files, provider usage when available, clearly labelled proxies otherwise, repeated-query definition, success/failure/cancellation/blocked counts, and documented eligible denominators. Distinguish fixture, replay, deterministic and actual provider evidence. No provider prices or savings are invented.
4. **Autohealth.** Run bounded deterministic checks for platform availability/configuration/dependencies/permissions, supported Gherkin/config/locator/index/artifact problems, repeated failures or slow setup, and stale/duplicate/contradictory/oversized/unused knowledge or skill candidates. Return severity, stable finding fingerprint, evidence and recommended action. Unsupported static patterns and unused/flaky/slow heuristics are candidates, not proven defects. Provider connectivity is checked only under its configured consent/execution policy.
5. **Local schedules and web workflows.** Expose on-demand checks and configurable schedules while the platform process is running. Show last/next execution, pause/error/cancellation/overlap handling and unavailable/missed checks. Keep read-only checking separate from any proposed remediation. No OS wake-up, cloud automation or unattended source/instruction modification is implied.

## Decisions and tradeoffs

- Start with deterministic ingestion and diagnostics; optional model enrichment requires separate configured data-sharing and credential authorization. Phase 4's temporary credential grant does not carry forward.
- Knowledge is advisory data. It cannot approve business requirements, shell execution, repairs, source writes or active instructions. Inferred claims remain visibly inferred and require review before promotion.
- Use stable source/capability keys and content hashes for deduplication; retain immutable revisions and explicit stale/superseded states. Deduplication must not erase distinct repositories or revisions.
- Keep runtime knowledge/docs private by default. Do not grow AGENTS.md or force all knowledge into every model prompt. Retrieve only relevant current records with progressive disclosure.
- Use one explicit skill destination per authorized repository. Phase approval does not install skills in the user's home, write external repositories, activate an existing candidate or authorize rollback of active instructions. Demonstrations can use owned synthetic destinations with clearly identified QA actors; real activation requires its own exact-bundle approval.
- Compare the active baseline and candidate on identical versioned cases/configuration, including safety refusals and held-out variants. Deterministic script/workflow evaluation and actual agent behavioral evaluation are distinct evidence classes. If a required agent comparison cannot run, report it as missing rather than substituting text/format checks.
- Model tokens remain null when not exposed. Proxy metrics never become billed-token claims. Rates retain their denominator, eligibility rule and time window. A cost/quality improvement claim requires comparable measured outcomes.
- A scheduler belongs inside the local modular monolith and supervises bounded read-only jobs. It does not grant execution trust to imported scripts or authorize fixes.

## Dependencies, risks and unresolved approvals

Existing knowledge/skill lifecycle policy and evaluation rubrics remain authoritative. There is currently no active product skill: earlier candidate trials include a rejected discovery v1, exploratory discovery v2/Playwright results and format-only Karate validation. They cannot be silently treated as an effective active baseline.

Primary risks are misleading metrics, permanent documentation noise, secret-bearing workflow evidence, overfitted skill comparisons, conflicting active instructions, stale source identities and noisy unused/flaky/setup heuristics. Limit the initial deterministic supported patterns and disclose gaps. Keep all hard safety gates independent of aggregate scores.

Entry exception is granted and recorded in phase-status.md. Any live provider session reuse, provider spending budget, actual user skill activation or external write remains a separate authorization when a concrete reviewable result requires it. No such permission is inferred from phase approval. Avoid cloud jobs or billing changes solely to bypass existing CI debt.

## Validation and stop

Before calling the phase complete, demonstrate the knowledge lifecycle and approved reversible skill workflow, run the labelled health dataset and web journeys, publish comparable metrics with limits, and update documentation/skills with their actual evaluation/activation state. Produce the mandatory completion report including failing/missing checks. Stop after Phase 6; additional work requires a new approved phase proposal.
