# Primary-source research

Accessed 2026-11-05. These sources support compatibility constraints and API capabilities. They do not prove this repository has implemented or executed anything. Versioned dependencies will be selected, pinned and validated in the phase using them; documentation can change.

| Topic                      | Source                                                                                                 | Consequence for this design                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node release status        | [Node.js releases](https://nodejs.org/en/about/previous-releases)                                      | Node 24 and 26 are listed as LTS at research time; prefer 24 initially for compatibility and pin the patch in P1.                                                           |
| Backend lifecycle          | [Fastify LTS policy](https://fastify.dev/docs/latest/Reference/LTS/)                                   | Validate the chosen Fastify/Node/plugin combination against supported versions; no benchmark claim made.                                                                    |
| SQLite WAL                 | [SQLite WAL documentation](https://www.sqlite.org/wal.html)                                            | Local disk only; WAL still has one writer. Require engine 3.51.3+ or documented fixed backport for the reported WAL-reset bug, and verify the driver's embedded engine.     |
| Gherkin                    | [Cucumber Gherkin reference](https://cucumber.io/docs/gherkin/reference/)                              | Use official grammar semantics for Backgrounds, outlines, Examples, tags and structure.                                                                                     |
| BDD compiler               | [Playwright-BDD maintainer repository](https://github.com/vitalets/playwright-bdd)                     | Generates native Playwright tests from features; pin a supported Playwright/compiler pair.                                                                                  |
| Playwright code generation | [Test generator](https://playwright.dev/docs/codegen)                                                  | Inspector interaction recording and locator assistance are documented; do not assume a public embeddable semantic-event stream.                                             |
| Public observation hooks   | [Playwright Page API](https://playwright.dev/docs/api/class-page)                                      | Public initialization/binding APIs are candidates for the limited observation layer; validate their recorder use in P2.                                                     |
| Accessibility evidence     | [Playwright ARIA snapshots](https://playwright.dev/docs/aria-snapshots)                                | Use public snapshot facilities where the pinned release supports them; do not rely on removed/private accessibility APIs.                                                   |
| Trace limitations          | [Playwright tracing](https://playwright.dev/docs/api/class-tracing)                                    | Browser tracing is useful evidence but is not a business-assertion or narration engine.                                                                                     |
| Karate runtime/build       | [Karate install and Gradle guidance](https://docs.karatelabs.io/getting-started/install-dependencies/) | Documented 2.x uses Java 21+; verify exact artifacts, runner and flags rather than copying a sample uncritically.                                                           |
| Karate caching             | [Calling features](https://docs.karatelabs.io/reusability/calling-features/)                           | Distinguish feature-scoped `callonce` and run-wide `karate.callSingle()`; scope shared cached setup carefully.                                                              |
| Audio capture              | [W3C Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/)                           | Permission/secure-context requirements constrain platform-tab microphone capture.                                                                                           |
| Audio recording            | [W3C MediaStream Recording](https://www.w3.org/TR/mediastream-recording/)                              | Detect supported encoding and chunk behavior; no single codec guarantee.                                                                                                    |
| Codex integration choice   | [OpenAI: Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)                  | App-server is designed for product integration; SDK remains an alternative for simpler programmatic jobs.                                                                   |
| Codex protocol             | [OpenAI: Codex app-server](https://learn.chatgpt.com/docs/app-server)                                  | Persistent tasks, events, interruption and approval requests support the interactive adapter. Prefer local stdio; protocol claims require pinning and contract tests in P3. |
| Skills layout              | [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills)                                    | Repository skills use `.agents/skills/<name>/SKILL.md`, frontmatter name/description and progressive disclosure; proposals must stay outside active discovery paths.        |

The architecture, threat model, thresholds and phase allocation are project recommendations inferred from requirements and these constraints; they are not guarantees made by the cited projects. No current pricing, account entitlement, benchmark, token savings, native report compatibility or OS certification is inferred from documentation alone.
