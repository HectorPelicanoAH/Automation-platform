# Reviewed generation conventions

Scope: implemented Phase 3 behavior, with final model and cross-system acceptance tracked in [the report](../phase-3-report.md). This is curated procedural knowledge, not an automatically activated skill.

- The promotion starter already has `PromotionsPage.visit` and `expectPromotion`, scoped uniqueness checks, shared fixtures, a customer builder and thin business steps. The controlled generation input removes only the Then binding. Both the declared provider fixture and a separate real Codex trial passed actual negative/positive native validation; their evidence remains distinguished in the report.
- Source index reuse depends on file hashes, include/exclude policy and extractor version. A preferred branch label does not check out a branch or identify uncommitted contents. Revalidate retrieved file hashes and source permissions before trusting a proposal.
- Evidence identifiers reference the original recording event or narration segment. Existing features provide reuse context and cannot establish a new business requirement. Missing thresholds must remain questions for human review.
- `test` imported as `base` and exported through `base.extend(...)` is still a reusable fixture. Reuse plans copy exact indexed symbol names; “Given/When bindings” is descriptive text, not a capability identity. These two distinctions were confirmed by real generation failures and regression checks.
- Repository paths and parser-status notes are not recording evidence. Discovery skill v1 was rejected for mixing them into behavioral claims; the separately evaluated v2 proposal keeps those fields distinct. Neither version is active.
- Gherkin approval, staged execution trust and managed diff application are separate grants. A passing run is insufficient for application. Contract edits/rejection invalidate dependent proposals and cancel active dependent work; applied history is retained.
- Codex metadata/catalog/schema checks verify protocol compatibility only. Real authenticated inference, skill behavior and model costs need their own evidence. Private credentials never belong in an index, prompt, repository or execution artifact.

Evidence: [generation tests](../../tests/generation.test.ts), [actual browser/native workflow](../../tests/generation-ui.spec.ts), [protocol boundary tests](../../tests/provider.test.ts), [live trials](../evaluations/phase-3-live-evidence.json) and [ADR 0011](../decisions/0011-reviewed-ai-generation.md). Recheck after changing these implementations. Confidence is limited to executed checks and these small synthetic trials; no general generation-quality or token-saving claim follows.
